# iOS 性能后续优化与评论自动分页

## 2026-11-02：Android 动态图片请求与滚动预取

针对 Android 动态头像、缩略图和封面比 iOS 加载慢的反馈，本轮仅调整图片加载链路。

- **修正图片地址**：在图片请求边界把已知 `iN.hdslb.com` 的 HTTP／协议相对 URL 归一为 HTTPS，保留路径、查询和片段。此前 Android 明文网络被禁用，而绝对 HTTP 地址又绕过了尺寸化 CDN 请求；iOS 已有相应归一化。
- **预取跟随阅读位置**：当前可见动态起点向前最多 8 卡，每卡头像与前两张封面，并发最多 2。可见与预取共用实际栏宽计算出的像素尺寸和 Scale，复用同一个 Coil 加载器及已有内存／磁盘缓存。窗口重叠保留任务；离页、后台、图库、全覆盖页面或宽屏播放器全屏时取消该预取方的任务，不清缓存。
- **合并正在进行的相同请求**：设备测试发现预取与可见请求并发时存在重复下载。现在只对共享动态图片 builder 标记的安全 BFS 缩略图，按最终 URL、尺寸、Scale 和回退源地址共享未完成任务；最后一个消费者离开才取消。结果按消费者复制，不另建结果缓存，也不让不同图片排进同一串行队列。
- 图库仍沿用原图请求；签名地址、动画及未知路径不做新尺寸变换。缓存容量、播放器行为和其他页面样式保持原样。

## 2026-10-25：延迟优先的增量优化

本轮从 `6b12b32d` 开始，优先减少加载竞争、重复计算和界面无关更新。保留全部已下载弹幕段、已准备的上层播放器、动态旧页和图片清晰度；不调整缓存容量、续播等待策略或弹幕刷新率。

### 已实现

- **双端弹幕增量排版**：解码后的段保持独立，正常追加仅处理新增段，不再展平、排序全部历史。每段保留排版及车道状态；乱序段到达时仅重算受影响的后续段，Android 同时复用文本布局。每帧继续读取真实播放器时间，按时间范围排除无关段，再二分取当前 5 秒窗口；跨段弹幕、下一段预取与缓存回看保留。
- **iOS 隐藏网页暂停 DOM 工作**：保留 WKWebView 文档、历史、会话和缓存，断开注入脚本的 DOM observer、取消待执行的 DOM 任务；恢复时更新配置及 bridge revision，并同步一次。媒体和 PiP 状态事件继续传递，隐藏前已排队的必要媒体状态也会同步。暂停 revision 处理 SwiftUI 合并快速隐藏/返回更新的情况，避免网页停在隐藏状态。未调用可见性接口的 Android runtime 仍默认工作。
- **iOS 搜索预取跟随阅读**：首屏先预热前 10 项，视频、用户和直播结果随出现的行分桶移动预取窗口，支持向前、向后和下一页追加。关键词、类型或排序变化会撤销旧任务；即使相同 ID 的行未重新出现，也会预热新结果首批。影视横向列表保留原布局及首批预热。沿用图片仓库的缓存、请求合并、取消和并发上限。
- **iOS 进度通知局部化**：播放位置由独立进度对象发布，只有控制条、字幕与弹幕等时间相关组件订阅。详情、评论不再因纯进度 tick 收到整个 ViewModel 的通知；业务状态照常更新。时间观察频率、实时总时长、seek、观看进度保存与续播流程不变。

### 比较方法

参考 [performance-optimization skill](https://www.skillsbot.cn/skill/4033) 的“识别瓶颈 → 建立基线 → 同负载比较 → 正确性回归”思路，没有安装或执行其中的工具指令。客户端指标以点击到可见首帧、再次打开、返回恢复、拖动回看及高倍速绘制为准，不套用网页加载指标。

弹幕对照使用同一份 30 段、每段 1,000 条的已生成数据，比较旧的每次处理全部历史与增量排版；输入生成不计入计时。累计布局访问由 **465,000 次降至 30,000 次**。Android 本机单次合成样本由 **48.83ms 降至 10.18ms**；这些是排版工作量及本地耗时，不是网络起播耗时。

完整起播链路已并行准备播放与查询续播；本轮保留其等待与首帧判定，不用从错误进度起播换取更短的加载显示。真实账号/CDN 的首帧分布和物理设备 120Hz、CPU/耗电仍需要实机数据。

## 2026-10-17：动态缓存与评论分页

日期：2026-10-17。基于已有性能基础修复继续增量修改，保留原有工作区内容。

## 用户可见行为

- 再次启动时，确认账号后优先展示该账号的动态快照，后台获取最新第一页。有更新时提示用户点击展示，不自动挤动当前内容。
- 动态页提供缓存清理入口；仅清理动态快照和动态请求缓存，不清登录、设置或观看进度，已显示卡片仍保留。
- 快照最多保存 3 个账号、每账号 300 条、7 天，总文件上限 8 MiB。保存完整分页边界，超过条数后保留前一次完整快照，避免丢行后使用错误游标。系统可回收缓存目录。
- 图片预取跟随卡片出现位置，预取后续少量卡片，继续使用原有总量和并发上限。
- 动画表情复用图片仓库和请求合并，在后台按显示尺寸下采样；减少动态效果时使用静态首帧。
- 视频详情短时缓存 30 秒、最多 32 项，按会话版本隔离；不缓存播放地址或互动状态。
- 视频详情评论滚动到末尾附近自动加载，失败显示重试。重复评论合并，循环游标停止，隐藏页面撤销追加请求。

## 测量与边界

新增 `videoStartup`，从进入原生视频路由到当前播放器真正显示首帧，保留原有 `firstFrame` 播放准备阶段指标。网络诊断记录实际请求次数，不改变原重试策略。

动态作者列表改为增量整理。尚未裁剪运行中的长列表或引入行高缓存；需要长时间真机滚动的内存、帧率证据后再决定，避免破坏视觉锚点。没有声称具体提速百分比，没有改变 Android 行为，没有发布或安装真机版本。
